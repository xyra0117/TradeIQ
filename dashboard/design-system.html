为什么有这份文档：设计稿只画了导航/卡片/表格几个代表件，页面实际用到 268 个 class， 其中 197 个当时没有任何规格 —— 结果是它们各自带着裸 hex，切到白天模式不变，视觉对不上。 这份文档 + index-v2.html 里的 v2-system 层是同一套值，改一处两处同步。

01 · 原则

语义优先于字面

样式写 var(--up) 不写 #ff5a68。涨跌、品牌、状态各有唯一入口， 换主题时只需换 token，不用碰组件。

双主题等宽

每个 token 在暗色/浅色都有定义，且是同一个名字。任何组件不允许只在一套主题下好看。

网格只是质感

页面背景网格用 --grid-line + opacity: .2。 它不该和数据抢注意力，看到就说明太重了。

图表不描边

饼图/环形图的扇区 borderWidth: 0， 靠 spacing 留 2px 底色缝做分隔。描边色取暗底会在新底色下变成一圈粗黑边。

折线的描边是数据

折线/面积图的 borderColor 就是线本身，必须保留。 区别：封闭图形的边框是装饰，开放曲线的描边是数据。

数值有出处

间距只从 4px 阶梯取，字号只从 7 档取，层级只从 5 档取。散落的 13px、7px、19px 都该换掉。

不要框套框

容器有描边、里面的控件又有描边 = 两层框。只允许一层： 要么外层是容器（描边，内部控件无描边），要么反过来。绝不叠加。

按钮不用描边

全站按钮一律 border:0，用底色 + 文字色区分状态。 唯一保留描边的是输入框——描边表示「这里可以输入」。

不用渐变条表意

涨跌靠数值本身的颜色表达，不用大面积渐变色条。 色条只保留 2px 细线做定位，不抢数据。

两个会静默炸掉的坑：
① CSS 变量自引用——--text-primary: var(--text-primary) 会让该变量变成「未定义」， 凡是 color: var(--text-primary) 的元素文字全部透明。 批量替换色值时最容易撞上，替换后必须扫一遍 --x: var(--x)。
② JS 对象重复键——换色映射表里两个键写成同一个值， 后者会静默覆盖前者，切到浅色时对应的那类元素就不换色了。

02 · 色彩

2.1 表面阶

相邻表面在暗色下差约 0.5–1% 相对亮度，白天拉到约 6%，否则白底一片糊。

暗色底色不能压到纯黑。纯黑（相对亮度 < 0.006）看着省电，实际整页发闷、 卡片边界糊在一起，长时间盯屏也更累。当前底色 #141922（0.010）， 约为纯黑的两倍，是长时间看数据比较舒服的档位。

4.1 间距阶梯（4px 基）

控件内边距（--ctl-*，独立体系）

控件内部的 padding 不跟 --s* 混用，单独三个变量：

--ctl-h: 32px 全站控件统一高度

--ctl-px: 12px 按钮左右内边距

--ctl-gap: 12px 下拉箭头到右边缘的留白

使用场景

按钮/输入框/下拉 → --ctl-*；页面区块之间 → --s*。 两者不混用，避免同一个 12px 在两套含义里漂移。

4.2 圆角与层级

圆角

--r-sm: 6px 控件、标签、进度条

--r-md: 10px 卡片、浮层、弹窗

--r-full: 999px 药丸、圆点

禁止拼接式圆角。像 border-radius: 6px 0 0 6px 这种「左圆右方」 是为了让相邻控件拼成一条，属于框套框的变体，一律不用。

层级

--z-nav: 10 侧栏 · --z-drawer: 35 详情栏

--z-topbar: 40 顶栏 · --z-float: 45 悬浮按钮

--z-modal: 60 弹窗 · --z-toast: 80 下拉浮层

边框使用规则

可以描边：卡片、浮层、输入框、表格分隔线

禁止描边：按钮、分段切换、标签徽章、导航项

同一区域最多一层描边，容器和内部控件不能同时描边。

06 · 布局

结构

整页 CSS Grid，两列两行：216px | 1fr，行高 56px | auto | 1fr。 侧栏 sticky，顶栏固定在第一行。

响应式

≤900px 收成单栏，侧栏变顶部横排，同时必须把 grid-column 收回 1 —— 否则 grid-column:2 会撑出一条隐式列，页面裂成两半。

已知陷阱

不要给顶栏用 position:sticky：外层是 grid，sticky 元素以自身网格行为定位基准， 页面变高时会被钉在视口中间。改用 position:relative。

溢出

grid 子项必须 min-width:0，否则被内容撑爆会产生整页横向滚动条。图表容器同理。
