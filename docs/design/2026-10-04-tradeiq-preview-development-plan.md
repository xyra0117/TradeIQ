# TradeIQ 新版前端功能预览实施方案

日期：2026-10-04。状态：真实数据与测试写入范围已确认；具体实施方案待确认，尚未开始业务代码改造。

## 目标与已确认范围

把已确认的黑白桌面 UI 开发成可以验收真实功能的本地预览版。沿用现有八个模块、33个视图、双主题与 Remix Icon，不重新设计视觉风格。用户已选择“真实数据功能预览，写入操作使用独立测试数据”。

现用 `dashboard/index.html`、根路径入口及现有后端服务保持原样。预览验收完成后，再由用户明确授权部署、替换入口或清理文件。本次不包含上线、Git push、数据库结构变更、密钥配置变更或全局依赖安装。

视觉与功能依据：

- `docs/design/2026-10-04-tradeiq-design-system.md`：统一设计规范。
- `docs/design/2026-10-03-tradeiq-pages.md`：八个模块、33个视图清单。
- `docs/design/2026-10-04-tradeiq-ui-parity.md`：23组功能组件及真实开发要求。
- `dashboard/redesign/index.html` 与 `components.html`：交互、布局与组件基线。
- `dashboard/index.html` 与 `backend/app.py`：现有业务字段、计算口径与接口依据。

## 预览环境与数据隔离

建议本地预览使用 `127.0.0.1:5556`，端口可配置；当前 `5555` 服务继续运行。新入口为 `/dashboard/redesign/preview.html`，服务根路径只重定向到该预览入口。仅监听本机地址。

预览读取本地真实数据库的一致性副本。原数据库以 SQLite URI `mode=ro` 打开，并启用 `PRAGMA query_only=ON`，通过 SQLite backup 创建测试副本；不直接复制正在使用的 WAL 文件。当前数据库文件约3.51 GiB，副本需相近的初始磁盘空间，后续写入另有增量。

预览查询也全部使用副本。理由是现有部分 GET 接口会保存策略缓存、尝试补齐数据，不能仅依赖 HTTP 方法判断只读。复制时间和各数据源的最新日期在预览状态中显示；副本不会随当前版本自动更新。需要更新验收基线时，显式生成新的副本，保留上一份测试环境。

独立启动器复用已存在的业务计算与接口，不执行原应用的 `__main__` 启动流程，不调用 `init_db`、结构迁移、全量初始化或定时任务注册。原 `backend/app.py` 不改动。数据库连接必须强制定位到测试副本，其他业务数据库路径拒绝访问；对业务请求的结构变更语句实行拦截。若现有接口依赖结构升级，报告具体缺项，另行处理，不自动迁移。

预览写入包括导入、自选、持仓记录和测试同步，仅作用于副本；上传、任务状态、生成图片和日志进入独立运行目录。同步由用户明确点击后启动，写入副本，界面持续显示任务进度与错误。预览不启动后台定时采集，不向飞书、邮箱或其他外部服务发送消息。需要外部 OCR 或付费能力时，先明确实际能力、授权和费用条件；未接通时展示未接通状态，不用示例成功冒充。

数据库副本、上传文件和运行产物不进入项目或 Git。运行目录使用系统临时目录的独立 `tradeiq-preview-*` 路径；验收前保留，删除或清理仍需用户授权。

## 实现范围与现有接口

接口参数、字段、单位与缺失语义以源代码和当前界面为准，不把原型里的统一示例字段当成正式接口合同。

| 模块 | 覆盖内容 | 主要复用接口 |
| --- | --- | --- |
| 核心指数 | 市场总览、历史、晴雨表、相近盘面、四指数详情 | `/api/index/daily`、`/api/overview`、`/api/barometer`、`/api/index/kline`、`/api/index/minline` |
| 阶段涨幅榜 | 5/10/20日榜单、频次、TOP1历史 | `/api/leaderboard`、`/api/frequency`、`/api/leaderboard/top1` |
| 涨停拆解 | 日期、板块/连板筛选、关键词、简图与识别流程 | `/api/limitup` 及现有简图、识别状态接口 |
| 涨停合集 | 封板、炸板及历史/实时语义 | `/api/limitup/collection` |
| 主力净流入 | 东方财富、同花顺、行业/概念、市场历史及个股查询 | `/api/flow/*`、`/api/market/fflow/daily`、`/api/stock/<code>/fflow/daily` |
| 选股推荐 | 东方财富8策略、同花顺3策略、我的选股 | `/api/picks*`、`/api/conditional-picks*`、`/api/combined-picks*`、`/api/user-picks*` |
| 板块合集 | 全市场、自选、详情、核心/同领域角色 | `/api/sector-collections*`、`/api/user-sectors*` |
| 持仓 | 现持仓、买入、卖出、对账、交割、减仓计算与导入 | `/api/positions*`、`/api/trades*`、`/api/delivery/*` |

个股与指数图表显示真实行情，保留全历史数据、均线、成交量/额、MACD、五档资金、多选图例、同步范围与指针。交割图按真实成交日期及价格显示 B/S。所选日期缺失分时或指标时明确说明，不换成其他日期或虚构数据。

选股策略保持现有规则和各自 T+N 口径：条件/优选与低吸不能共用一套收益公式；冲高观察标明“不是买入信号”。所有金额转换按实际源数据单位完成，缺失值保留为空。历史样本、覆盖统计与预览图片以真实结果生成。

持仓、成交导入使用真实文件解析、映射、校对和去重流程，但确认后的记录仅写入测试副本。计算器按现有佣金、过户费、印花税及舍入口径实现，不重新定义收益。持仓变化导致已采用方案失效时给出实际状态。没有现有服务支撑的后台提醒不能宣称已发送。

## 开发顺序

1. 隔离环境：更新结构约定，建立独立启动器、副本、连接与文件保护；先验证原库不能被预览修改。
2. 外壳与图表：完成真实交易日、导航、双主题、偏好、请求状态、股票/指数详情和图表联动。
3. 查询页面：接入指数、榜单、涨停、资金、全部策略、板块及持仓读取；逐个视图比对旧版同参数结果。
4. 测试写入：接入自选、板块成员、持仓/成交导入、计算与对账、明确触发的同步；验证写入只存在于测试副本。
5. 完整验收：逐项检查33视图与23组功能，保留正式验证摘要和截图，打开本地预览供用户测试。

中间功能完成只作为开发进度，不将未完成的视图或演示交互标记为完整功能。

## 验证与交付门槛

- 在内存数据库和临时副本中验证源库隔离、原路径误连拦截、测试写入、结构变更拦截与无定时任务启动；不在用户实际数据库执行测试写入。
- 对涉及的策略和图表运行项目现有回归命令：指数图表、条件优选/新、低吸两版、冲高、盘中 T 列；新增前端测试覆盖参数、单位、日期、缓存和旧响应覆盖。
- 浏览器覆盖1440、1920、2560px和双主题；检查33视图、侧栏、表格内部滚动、列设置、搜索、详情前后切换、关闭、图表范围、导入校对与错误重试。
- 对照现有版本的同日期、来源和参数结果；验证无数据、覆盖缺失、请求失败和未来窗口不足的真实状态，不能用0或示例值补齐。
- 记录旧前端 `dashboard/index.html` 和原后端 `backend/app.py` 的开发前后 SHA-256；核对根路径和现有服务仍正常，原始文件摘要不变。原库由现有服务继续更新时，不用整个数据库摘要变化误判预览写入。
- 交付包含启动方式、本地预览链接、数据副本时间、模块验收表、自动验证摘要，以及尚未接通的外部能力清单（若存在）。用户验收成功后再讨论上线切换，不自动部署。
