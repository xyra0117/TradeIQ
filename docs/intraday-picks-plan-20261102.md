# 低吸、追高、自定义选股：盘中筛选实施方案

日期：2026-11-02。状态：用户已确认，代码已实施，已完成自动化回归及真实行情接口、页面核验。盘后完整日线入库前仍显示待收盘确认。

## 要实现的结果

三个策略都支持在今天交易过程中按当前行情生成名单，显示“盘中预选”；收盘行情完整入库后，按原有收盘口径重新筛选，显示“收盘确认”。盘中符合的股票可以随着价格、成交量、资金变化进入或退出名单。

沿用既有条件开关、低吸参数、自定义分组与公式、数量标签、诊断和个股弹窗。历史日期继续使用对应日期的完整日线。

## 已核对的现状

- `backend/dip_picks.py::_daily_context` 明确拒绝尚未收盘的日期，并默认选择最近可用收盘日。
- 低吸、追高的名单、条件计数、未入选诊断，以及 `backend/custom_picks.py::screen_custom` 都依赖这个入口，因此三个策略一起受限。
- `backend/app.py::fetch_sina_quotes` 已提供实时价、昨收、开高低、累计成交量、累计成交额；全市场版本可基于基础股票表取数。现有量单位已从股换为手；实时成交额是元，转换到日线/公式单位时必须统一。
- 当前报价解析的 `time` 主要保存行情日期，实施时须同时保留实际时分秒，才能判断行情是否过旧；不能只显示请求完成时间冒充行情时间。
- 东方财富当日资金有现有采集入口，但全市场采集需要分页，不能假设资金与报价同时更新或能每秒重拉。
- 本轮只读检查：本地日线、盘面概览、指数日线最新为2026-10-30；资金已有2026-11-02的5261条东方财富记录，表中最新更新时间为13:49:50；交易日历覆盖到2026-12-31，并包含11-02。该检查只说明盘中资金记录存在，不代表全部股票的数据齐全或持续新鲜。
- 现有 `PicksResultCache` 已区分实时结果，但新模式需要进一步隔离名单、计数、诊断、分页和盘后结果的身份，避免误用历史缓存。

## 界面与使用方式

1. 在三个策略的日期附近提供“盘中预选 / 盘后确认”模式。交易日开盘后，用户可直接选择今天进入盘中预选，不受今天尚无日线的日期列表限制。
2. 盘中名单上方显示日期、行情采集时间、资金更新时间、可评估覆盖，以及“当前满足，收盘可能变化”。字段显示“最新价”“截至当前成交量”等相应名称。
3. 第一版复用现有刷新操作：刷新、修改条件或切换模式时重新筛选；不新增持续后台采集任务，不承诺逐秒扫描全市场。已有自动刷新若作用于这里，必须刷新完整筛选结果，不能只更新名单中的股价。
4. 条件数量小标签、为什么没选出来、自定义逐项检查使用与名单相同的一批盘中输入。查看诊断或翻页时复用这一批输入，显式刷新才换批次；换批次后清除旧诊断和旧分页。
5. 切到历史日期时使用对应日收盘确认；不使用当前实时价回算历史入选名单。盘后日线未完整入库时仍标“待收盘确认”，不把最后一批实时快照伪装成正式日线。
6. 当日没有后续T+1～T+5时正常显示等待；后续表现基准仍为最终入选日收盘价，盘中预选价格另标，不能作为历史收益的确定分母。

## 三个策略统一的数据口径

| 条件或字段 | 盘中计算方式 |
|---|---|
| 当日涨跌幅、低吸涨跌区间 | 当前价格相对当天行情昨收计算，沿用设置的边界 |
| 120日或自定义周期涨幅 | 以当前价暂代今天收盘，历史部分只使用今天之前的数据 |
| MA5/10/20/60、均线多头 | 当前价加此前完整收盘数据计算“盘中均线” |
| 当日最高/最低、振幅 | 使用截至行情时间的最高/最低；今天的振幅尚未最终确定 |
| 20日平均振幅 | 今天使用截至当前振幅，其余19日使用历史完整数据 |
| 成交量、成交额 | 今天使用截至当前累计量额，不预测全天；历史部分保持原单位 |
| 当日量/此前5日均量 | 当前累计成交量 / 此前5个交易日全天平均成交量 |
| 3/5/10/20日主力累计 | 今天截至资金更新时间的东方财富净额，加此前相应交易日净额；原有窗口及门槛不变 |
| 上证、大盘下跌家数 | 当天实时指数与对应范围的有效市场行情；旧盘面日线不代替当天实时值 |
| 追高“未涨停” | 当前价低于可核验涨停价；盘中打开后可以暂时符合，之后封板可退出 |
| 自定义close、high、low、volume等 | 仅第0日映射为当前实时值；REF及窗口偏移保持原交易日语义 |
| 自定义资金/大盘字段 | 有新鲜有效数据才能计算；缺失保留为数据不足，维持现有分组的真假/未知语义 |

特别说明：早盘累计量尚小，“缩量”条件更容易满足；下午成交量增加可能使股票退出。这是当前累计量口径的结果，不自动乘以时间比例估算全天成交量。若以后需要“预计全天量”或“同一时刻量比”，应作为独立指标，另行核对历史分钟量覆盖，不偷偷改变原条件。

## 数据有效性与缺失处理

- 每只报价必须携带当天日期、实际行情时间和有效价格；停牌、无成交、错日期、过期行情不当作正常报价。
- 行情、资金和大盘分别报告时间。午休显示上午最后有效状态，盘前/节假日不把上一交易日快照标为今天盘中。
- 当前资金优先取5分钟内的本地同源记录；覆盖不足或主动刷新时直接读取东方财富既有push2接口，仅放入本批内存。“更新东方财富资金”重新抓取当前批次，不触发旧浏览器采集器或写库。失败或超出允许时效则资金条件为数据不足。关闭资金条件后不再因资金缺失阻止纯价格筛选。
- 不混用同花顺与东方财富资金。东方财富两个既有同口径接口按既有取源规则衔接，并保留源标识。
- 大盘家数需保留有效覆盖情况；缺失股票不计为平盘，不能在覆盖明显不完整时直接认定已通过2600家门槛。优先使用经日期/时间核验的同范围汇总数据，无法保证时提示大盘数据不足。
- 历史连续性、价格参考异常检查继续生效。实时昨收与本地历史参考不一致时不悄悄跨越价格断点。
- 本轮目标是实时筛选，不保存盘中首次入选历史，也不回放历史某分钟的名单；这些能力需要另定记录方案。

## 验收标准

1. 交易日上午/下午，今天没有完整日线时，三种策略都能基于模拟及可获得的真实盘中数据返回结果，而不是统一等待收盘。
2. 同一批实时输入下，名单、独立数量、诊断及自定义逐项计算一致；条件开关和低吸区间边界维持原意。
3. 最新价、均线、当前量额及累计资金计算有独立样例核对，转换单位正确；历史窗口不含未来记录、不重复今天。
4. 资金缺失/过旧、报价错日、午休、停牌、节假日、大盘覆盖不足、盘后日线部分入库均有明确行为。
5. 所有开启资金条件的策略保持数据依赖；关闭后纯价格筛选仍可工作。自定义AND/OR遇到缺失数据保持原三态逻辑。
6. 日期、策略、参数、模式或批次改变后，迟到结果不覆盖当前页面；盘中结果不持久保存为稳定历史结果。
7. 收盘确认时重新计算正式名单，T+1～T+5仍以入选日正式收盘价为基准；历史日期结果保持一致。
8. 运行低吸、追高、诊断、自定义、缓存、市场背景和相关指数回归，并在浏览器验证今天/历史、刷新、数量标签、诊断、分页、个股弹窗和盘后切换。只完成模拟时如实标明，真实交易时段未验收不宣称已完成实盘验证。

## 已实施契约

- 共享适配器：`backend/intraday_picks.py`。历史库以只读方式附加到内存连接，临时视图替换第0日；查询阶段启用query_only。原始数据库、历史筛选公式及后台采集规则保持原口径。
- 入口：三个Tab共用“盘中预选（今日） / 盘后确认”。模式单独保存；点击盘中入口转到今天。改条件、查数量、诊断、分页都携带同一`snapshot_id`；主动刷新建立新批次。30秒内无指定批次的请求可复用，批次保留15分钟，最多8批；过期明确提示刷新。
- 行情时效120秒，资金300秒；午休以11:30、收市后以15:00作为过旧判断锚点，但未来时间仍与实际时钟比较，允许数据源收市后更新同日收盘报价。完整收盘日线就绪后沿用原收盘计算。
- 大盘下跌家数展示“已确认下跌～已确认下跌+未知”；只有整个范围都能确认通过/不通过时才判断2600门槛。自定义公式要求精确家数时，存在未知即保留未知，不补0。
- 当前累计成交量不放大推算全天；新浪股数换算为手、金额元换算成日线的千元。资金仍为元，东方财富`f124`核对实际更新时间，0与缺失分开。
- 盘中入选日不形成T+N收盘基准、不持久缓存成稳定历史结果。此前已收盘的历史名单与T+N路径继续保留。
