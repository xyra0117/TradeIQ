# 选股推荐日期结果复用

2026-10-07：修复已查看日期反复加载。

## 原因

系统推荐与同花顺推荐读取 `stock_picks` / `stock_picks_ths`；条件选股、条件选股新、条件优选及组合选股已有相应快照。低吸、追高、冲高观察、自定义选股则读取原始本地数据计算，不保存 SQLite 策略结果。

前端没有统一复用：低吸、追高、冲高观察、自定义选股每次进入都请求；部分策略只有页面内缓存；旧条件缓存24小时过期，部分只保存非空名单，即使命中仍后台重算。数据库有名单并不保证页面直接显示。

## 当前行为

- 所有自动筛选策略使用 `dashboard/picks-result-cache.js`。以接口、日期、完整查询参数作为缓存身份；自定义策略增加完整分组配置、分页、搜索和诊断代码。条件开关、资金门槛、缩量比例、低吸周期与区间参数均独立区分。
- 正常成功的零入选结果也保存。接口失败、未就绪、日期不一致及未落库提示不保存。指数分时必须有同日有效数据，缺失分时继续正常显示缺失状态。
- 成功的稳定结果存入浏览器 Cache Storage `tradeiq-picks-results-v1`，不设24小时过期。`tradeiq.picks.results.v1` 保存最多约3 MiB的快速副本；快速副本容量不影响完整历史存档。页面内缓存提供即时往返，同一结果的并发请求共用一次计算，渲染使用副本防止行情更新污染缓存。
- 清除浏览器站点数据、浏览器存储限制及更换浏览器/网址会影响本地保存；存储不可用时，当前页面仍可复用。缓存不是跨设备的 SQLite 策略结果表。
- 最近日期入口跨日、未完成T+表现跨日、盘中结果或当天对应T列需要更新时，先显示已有内容，再后台更新；成功更新只通知当前相关策略，原有实时行情更新仍保留。盘中结果不进入稳定存档。
- 点击“刷新结果”绕过缓存；低吸/追高与优选同时刷新该日附属统计和图表。同步完成后缓存失效，以读取更新后的数据。主动修改历史原始数据后可以手动刷新。
- 保留策略、日期、条件参数与请求序号守卫，旧响应不能改写新视图。自动同步不再把已确认的空名单当作缺数据。
- “我的选股”仍按现有添加/删除流程读取，它是可编辑的用户名单，不是自动筛选策略。

## 验证

- 新回归先复现：冲高观察 A日期 → B日期 → A日期，实际筛选请求为3次，修复后为2次；显式刷新增加1次。
- `node dashboard/test-picks-result-cache.cjs`：全部11个自动策略查询入口、空结果、参数隔离、页面重开、超过24小时的历史结果、失败/缺数据/日期不一致、并发合并、强制刷新与旧请求竞态、T+跨日更新、存储拒绝、快速缓存容量上限及完整存档恢复。
- 11项选股、条件缓存、市场背景、热门板块和指数前端检查全部通过，页面/外部脚本语法及差异格式检查通过。
- 当前本地真实页面：2026-09-30冲高观察181只，2026-09-29为192只；往返到09-30直接显示181只，页面重开后重新选择09-29与09-30，分别直接显示192与181只；手动刷新进入筛选态并重新完成。低吸与追高同日空名单往返也直接恢复，浏览器无运行错误。浏览器验证记录放系统临时目录。

本轮只改当前桌面前端、对应回归与说明；不修改后端筛选规则、SQLite结构、真实数据或独立设计原型。
